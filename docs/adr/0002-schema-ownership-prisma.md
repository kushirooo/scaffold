## Context

The baseline creates `users`, `credentials`, `sessions` and `password_reset_tokens` with
hand-written SQL in `src/database/migrations.ts` and a custom runner behind a raw `pg`
pool. The locked stack requires Prisma with schema-first migrations. No shared or staging
database exists yet and local data is demo-only, so squashing is free now (D3,
`SPRINT1_PLAN.md` §1.2). Three pressures shape the decision: US02 is built in parallel and
needs fields without forking schema history; US02 creates an account before a password
exists, so a non-null hash would force a fake credential (D4); and Prisma 6/7 client
generation against a NestJS ESM project (`"type": "module"`) is the top technical risk
(R1) because the client must boot in the real build.

## Decision

1. **One schema owner.** `prisma/schema.prisma` has exactly one owner — the backend
   implementation owner (Member 2; `backend-dev` in `COLLABORATION.md`). US02 requests
   fields; it does not edit the schema (§11.5, §21 `CODEOWNERS`).
2. **One squashed baseline (D3).** Delete the custom migration runner, `migrate.ts` and the
   `pg` `DatabaseModule`; add `prisma/schema.prisma` and a single `init_auth_schema`
   migration. Every later change is additive: edit → `prisma migrate dev` on a developer
   machine → review SQL → commit schema plus migration. CI/Railway run `migrate deploy`
   only; no `db push` outside a throwaway spike, no down-migrations (fix forward).
   `src/generated/prisma/` is gitignored, regenerated by `postinstall`/CI, excluded from
   lint/format/coverage but kept in `tsconfig`; Prisma is pinned and the lockfile committed
   (§18.3).
3. **Nullable credential (D4).** `Credential.passwordHash` and `passwordUpdatedAt` are
   nullable. Login treats a missing hash as invalid with the same generic 401 and a dummy
   argon2 verify; reset/change upserts set the hash. "No password yet" is a valid state.
4. **Target invariants.** Email unique and stored lowercase at every write; one credential
   per user (`user_id` PK); cascade delete for credentials, sessions and reset tokens;
   `revoked_at` is per-device logout; reset tokens single-use via conditional update and
   stored only as SHA-256; `token_version` monotonic; `UserRole` and `ResetTokenPurpose`
   are database enums (§18.1–§18.2).
5. **Prisma ESM risk and fallback (R1).** Use generator `prisma-client`,
   `moduleFormat = "esm"`, output `../src/generated/prisma`. Day 1 is timeboxed to a spike
   booting the real Nest build; Gate G1 at 15:30 decides. The documented fallback is
   `moduleFormat = "cjs"` plus `createRequire`, then a decision with the Lead before Day 2.
   Silently falling back to `pg` is forbidden (§20 R1, §17).
6. **Seed.** `prisma/seed.ts` imports the exported `HASH_OPTIONS`, refuses production
   unless `ALLOW_DEMO_SEED=true`, and seeds inactive and no-password users for the 401 and
   activation paths (§18.4).

## Consequences

- One schema authority, one migration history, typed repositories; US01/18/19 share the
  session, credential and reset-token tables instead of growing parallel ones. The raw
  runner and hand-written SQL repositories are deleted (§18.5).
- US02 loses direct schema edits; each field becomes a request to the schema owner. Slower,
  but it prevents merge conflicts and divergent history.
- The nullable credential removes the fake-password workaround but every hash consumer must
  handle `null` explicitly.
- **Environment constraint.** This checkout has no Docker daemon or local PostgreSQL
  (`COLLABORATION.md` §8). Validation, generation and SQL diffing run locally; applying
  migrations and e2e are deferred to CI/staging as `DEFERRED (no DB)`. Offline baseline SQL
  can be produced with `prisma migrate diff --from-empty --to-schema-datamodel`. No report
  may claim "migration applied" without the command actually running.
- If the ESM spike fails and the CJS fallback is chosen, import sites and build config
  change; that is a recorded ADR amendment, not a silent rewrite.

## Alternatives considered

| Alternative | Why rejected |
|---|---|
| Keep raw `pg` and the custom runner | Locked stack is schema-first Prisma; no typed client or single reviewed history |
| CJS generator from the start | It is the fallback; the project is ESM and CJS adds `createRequire` friction |
| `prisma db push` without migrations | No reviewable SQL or history; unsafe for staging; violates schema-first |
| A migration history per workstream | US02 owns no schema; parallel histories diverge and cannot be squash-merged |
| Non-null hash with a placeholder password | Fake credential and a security smell; D4 chose a nullable field |
| `pg` repositories alongside Prisma schema | Two access paths and transaction models; §18.5 replaces both |
